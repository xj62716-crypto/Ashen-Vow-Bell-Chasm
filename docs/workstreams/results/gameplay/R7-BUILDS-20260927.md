# R7 构筑功能收口记录

日期：2026-09-27。范围是 R7 非路线功能；正式路线生成与路线失败项按用户要求冻结，由用户自行实机跑，不在本记录中改动。

本轮把“基础→核心→成型”从卡片文案落实为运行时状态。`PlayerCombat.build_stage` 和 `build_synergies` 是唯一状态源，`RuneCatalog` 根据职业、核心和联动数量计算阶段；祭坛选项携带阶段和即时行为字段，HUD 可以直接消费，不需要再猜测当前强化属于哪一层。

随后补齐了祭坛供给的可靠性：已有核心后，候选会优先包含尚未取得的已编写联动伙伴；仍有未取得职业核心时保留一个核心候选；第三个位置优先来自当前分支的可立即使用扩展。每张候选还标注 `offer_role`（路线、战斗或风险）和 `immediate_behavior`，避免随机连续发出与当前构筑无关的卡片。该调度不改变首祭坛的三核心开局，也不修改路线生成。

已接入的五组实际联动：

- 残影＋返刃：弹反后下一次真实挥刀保留第二攻击原点，仍受真实挥刀和遮挡限制。
- 裂地＋飞檐：蹬墙后获得短暂横扫窗口，可在未落地时接低位横斩。
- 塑形＋冰：构造墙/平台/风井第一次被使用时触发冰壳碎裂，对附近可见敌人施加真实冻结。
- 咒印＋火：确认击杀后向附近可见目标传播标记；引爆同时留下灼印状态，不增加隐藏伤害源。
- 风暴＋塑形：创建承重表面时恢复受限的空中资源、冲刺和短暂跑酷事件，命中构造路线上的目标时再延长一次空中窗口。

敌人新增灼印生命周期和清理路径；灼印只改变护盾/控制窗口与可读状态，不在后台伪造击杀。所有新增状态都在重试、切换职业和死亡时随现有生命周期清理。

## 2026-09-27 状态接口收口

为避免 HUD、祭坛和后续数值调参各自推导构筑阶段，新增 `RuneCatalog.build_state()` 与
`PlayerCombat.build_state()`。接口统一返回职业、核心与扩展数量、当前阶段/标题、已激活联动、
缺失核心、流势/职业资源和当前技能意图；不改变已有存档 ID 或随机供给规则。

覆盖验证：两职业四核心逐项独立获得并进入 stage-one，`r7_build_progress_checks.gd` 32/32；
其余 R7 联动、敌人和生命周期回归保持 18/18、57/57、10/10。该接口仍只暴露真实运行时状态，
不把路线人工通行、最终美术或声音试听改写成自动通过。

## 2026-09-27 高速地面流势收口

R7 的地面容错规则已进入正式 `PlayerCombat`：高速落地、滑铲和滑铲跳不会再因为落地事件
瞬间清空流势；只有慢速/静止落地先扣除可调的小额成本，随后按站桩衰减。`build_state()`
同时暴露 `flow_ground_active` 与 `flow_ground_threshold`，供 HUD、调参和后续录像工具读取。
构筑状态栏在满足条件时显示简短的“疾行 · 流势维持”，不会增加说明面板。

验证：编辑器解析通过；R7 构筑 32/32、构筑与敌人 57/57、生命周期 24/24、处决 10/10。
本轮完整 gameplay 回归的唯一失败来自此前冻结的路线专项：`boss_route_checks.gd` 1 项和
`grapple_route_checks.gd` 的 stage 2/3 空间路线项，按用户要求保留给后续路线实机处理。
